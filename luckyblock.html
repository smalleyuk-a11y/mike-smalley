LuckyBlock Casino

Streamlining Casino Sign-Up

Redesigning the LuckyBlock sign-up flow to eliminate friction points, streamline player onboarding, and optimise welcome offer conversion.

Team

Product Designer (Me), Product Manager, Front-end Developer] A/B Testing Specialist

Tools

Figma, Hotjar, Google Analytics, Lyssna

Timeframe

12 weeks

The Problem

Many players dropped off during sign-up before reaching the lobby, and many who completed it never deposited. The flow asked for four fields upfront, including a mandatory username, with unclear password requirements adding friction, and the deposit screen was hidden in the UI.

Research & Insights

Old design

User flow

  • Sign-up flow data showed users dropping out at username creation and password validation.
  • Mapping the user flow from register to play showed multiple unnecessary steps between sign-up and deposit
  • Interaction data and screen recordings showed users struggling most with the username: names already taken, strict requirements and hesitation over what to choose
  • Competitor benchmarking showed SSO (e.g. login with Gmail), fewer initial fields and offers visible from the first step. Some avoided mandatory usernames, but that wasn’t possible here because a username was a backend requirement. Most platforms kept the deposit bonus visible throughout the signup process.

Ideation & Strategy

Before flow

Initial wireframe

  1. Flow mapped for improved cognitive load. A minimal first screen captures users, with the optional referral code kept closed to reduce cognitive load further, while the extra checkboxes move to step 2.
  2. Google and Wallet Connect sign-in added at the start. Players can skip most of the manual registration.
  3. Bonus offer front and center as it’s the biggest encouragement for sign-ups.

Original sign-up

Redesigned sign-up

  1. Remove friction with username suggestions Auto-generated username suggestions. The username is mandatory, but the friction around it is removed, and users can still customise it if they choose.
  2. Login Updated Login reworked to include the new sign-in methods. The forgot password and reset password journeys stay consistent but are updated to look seamless.

New optional deposit screen added to end of flow

  1. Optional deposit step added to flow. It encourages users to become active players in a logical flow.
  2. Clear messaging Requirements visible from the start and clearer error messages. Pointless placeholder text removed.

Before input experience

New experience with multiple improvements

Design & Testing

Full new sign-up flow

I built the final UI using the existing design system, then tested a prototype through Lyssna with eight participants. The testing was qualitative, helping me find points of confusion rather than statistically validating the design. The SSO methods weren't part of this test, but were included in the later A/B test.

Usability test

Some testers weren’t sure whether their account would be created if they didn’t deposit money on the optional final step. On review, the cause was clear: the flow had no success message. I combined the deposit page with the account-created confirmation to keep the flow simple.

One tester found it was odd that the username could only be generated, not typed. I solved this in the live version by having the text be selected immediately, so it's clear it can be edited.

A/B test

After the Lyssna test, I handed the final designs to our A/B testing specialist, who ran the revised sign-up, including the new Google and Wallet Connect sign-in, against the existing flow. Sign-ups increased by 11%.

Outcome

  • 11% increase in sign-ups against the existing flow
  • Registration simplified while keeping the backend username requirement

Login also updated with added SSO

Reset password updated to match latest UI changes

What I Learnt

This project taught me that a technical limitation doesn't necessarily mean a bad user experience. The username couldn't be removed, but I could make it feel effortless. I also learned that testing can uncover problems I wasn't originally looking for, which helped me improve the wider journey.
