LuckyBlock Casino

Casino Sign-Up

Redesigning the LuckyBlock sign-up flow to eliminate friction points, streamline player onboarding, and optimise welcome offer conversion.

Role

Product Design

Tools

Figma, Hotjar, Google Analytics, Lyssna

Timeframe

6 weeks

My Role

I owned the UX and UI design for the revised sign-up experience, working with the existing design system and collaborating with product and development to account for technical constraints.

  • Analysed user data and competitor experiences to identify friction points and opportunities to improve registration conversion.
  • Mapped user flows and developed wireframes to explore alternative onboarding approaches.
  • Designed the revised sign-up experience using the existing design system and accessibility standards.
  • Conducted usability testing with eight participants via Lyssna to identify friction and validate user understanding.
  • Iterated on the experience based on testing insights, including introducing a post-sign-up deposit prompt.
  • Validated the final design through A/B testing, resulting in an 11% increase in conversion.

The Problem

High drop-off during LuckyBlock's sign-up process was preventing potential players from reaching the lobby and becoming active users. The existing flow asked users to complete four fields upfront, including creating a username, while unclear password requirements added further friction. My goal was to identify where users were struggling, simplify the registration experience where possible, and make the welcome offer clearer without compromising the requirements of the existing system.

Research & Insights

Old Design

User flow

I started by analysing data from the existing sign-up flow to understand where users were dropping out. The biggest friction points were:

  • Username creation
  • Confusing password validation requirements
  • The number of fields presented upfront

I then benchmarked competitor platforms to understand how they approached registration. Several reduced friction by offering SSO, requiring fewer initial fields, and making promotional offers visible from the beginning of the journey. Some competitors avoided mandatory usernames altogether. This wasn't possible for LuckyBlock because a username was a backend requirement. This became an important constraint for the design:

If I couldn't remove the requirement, I needed to remove as much of the friction around it as possible.

Ideation & Strategy

Early draft

Initial wireframe

I mapped the existing and proposed user flows to find ways to make registration quicker and easier. I introduced Google and MetaMask sign-in at the start, allowing users to bypass most of the manual registration.

For traditional registration, I explored auto-generated username suggestions to reduce friction around the mandatory username requirement.

Sign-up 2 - Profile setup with auto-generated username

I then used wireframes to work through the structure before moving into visual design. I moved the username, referral code and additional checkboxes to the second step, keeping the first screen focused on the main action. Password requirements stayed visible, while error messaging was made clearer. The new sign-in methods also meant reworking the login flow so both experiences remained consistent.

Design & Testing

Username suggestion to solve a major pain point

Clear error messaging

I created the UI by applying the design system to ensure brand consistency and accessibility compliance. I tested the prototype on 8 participants via Lyssna to evaluate flow comprehension and friction. This highlighted an issue where some users were unsure if the offer was active or missed due to not using the referral code, which wasn't required for the offer. To solve this, I added an end-of-flow deposit pop-up so users could grab their reward, which had the added bonus of converting users to active players.

New screen added to encourage deposit after sign-up

Outcome

The revised sign-up experience was A/B tested against the existing flow and resulted in an 11% increase in conversion. The redesign reduced friction in the registration process while maintaining the backend requirement for usernames and making the welcome offer clearer.

Reset password flow updated to new UI

What I Learnt

This project taught me that a technical limitation doesn't necessarily mean a bad user experience. The username couldn't be removed, but I could make it feel effortless. I also learned that testing can uncover problems I wasn't originally looking for, which helped me improve the wider journey.
